# 2026-09-19 工作台终态与输出恢复验证

本记录对应本轮第 3、4、5 项。本地未提交工作树，不表示远端 CI 或新发行版已通过。
所有测试使用独立临时工作区，不读取用户工作台或私有求解器数据。

## 实现和使用入口

- `create_app(workspace)` 在初始化目录数据库、恢复证据或判断遗留任务之前取得
  OS 文件锁。Windows 使用 `msvcrt` 字节锁，POSIX 使用 `flock`；锁文件保留，
  不用 PID 或“文件是否存在”判断所有者。路径先规范化，同进程多个 app 同样互斥。
- FastAPI lifespan、CLI 的整个启动/运行区间、`app.state.close()` 和原有
  `app.state.jobs.shutdown()` 共享关闭流程。先停止接收请求，等待任务和整个 ASGI
  请求（包括同步端点、下载响应后台清理）退出，再停止持久化重试并释放所有权。
  `wait=False` 只使调用立即返回，所有权仍保留到旧写入者结束。请求内部触发关闭时
  使用后台关闭，避免请求等待自身结束。嵌入式调用方应管理 lifespan 或显式关闭。
- 终态先写 `.job-completions/<job_id>.json` 再更新 SQLite。每条失败终态有独立的
  六次自动尝试预算（第一次及五次重试，退避时间有界），不依赖浏览器详情轮询；
  正常关闭再做一次最终保存。重启只回放通过版本、工作区、项目、任务身份及完整
  终态字段验证的证据。坏记录保持原字节并记入 `app.state.persistence.recovery_errors`。
- 任务详情及项目摘要含 `persistence`：待保存时显示 `state=pending`、尝试次数及
  `evidence_saved`。HTML 和实际前端渲染均显示 “Result waiting to be saved.”。
  未写入目录的终态不会加入淘汰队列；重启回放中仍失败的终态也计入接收容量。
- 输出在移动旧目标或发布新目标之前写 `.output-transactions/<project>/<id>.json`。
  证据记录事务阶段、项目、位置、文件系统身份、SHA-256 和目录条目；快照登记前
  补快照身份，目录 artifact 元数据保存事务 ID，支持识别登记后返回前发生的崩溃。
- 项目页面有恢复入口 `/projects/<project>/recovery`；对应只读 JSON 清单为
  `/api/projects/<project>/recovery`。清单区分旧输出、本次生成输出、快照、已登记
  事务及冲突。带会话/CSRF 校验的恢复操作只复制到项目 `recovered/` 下确定的新位置；
  不覆盖既有路径，不删除原目标、旧备份或恢复证据。重复请求在身份匹配时返回同一位置。

## 测试先行的失败证据

1. 单实例与生命周期最初 **3 failed**：同进程第二 app 和第二进程均能进入，
   `shutdown(wait=False)` 在旧线程结束前未阻止第二实例。加入内核所有权后通过。
2. 真实 report 已生成并登记 artifact，但终态保存注入失败：无后续 HTTP 请求时目录
   一直 queued；永久失败没有可见持久状态。先 **2 failed**，随后重试、持久证据、
   容量保留及重启回放通过。
3. 输出真实子进程 `os._exit(23)` 后没有恢复 API/清单，首个备份边界回归先失败。
   现覆盖 report 文件和 comparison 目录各六个边界：移动备份前、移动备份后、
   发布前、发布后、快照复制后登记前、登记后返回前。重启清单不修改任何证据；
   恢复旧内容、幂等、项目隔离、目标改变、占用目标及损坏清单均有断言。
4. 待保存前端提示先 **1 failed**；Node harness 后续验证提示出现、目录更新后清除，
   并保持不轮询历史终态。既有历史分页、活动任务、旧响应乱序等断言保留。
5. 独立工程审查发现 HTTP 上传线程未被 JobManager 关闭等待：同步/非等待关闭
   两项先 **2 failed**，加入整个 ASGI 请求排空后通过；另验证响应后台清理和
   请求内部触发关闭。
6. 独立审查及集成追踪确认损坏 `recovered` 容器、底层 SQLite 异常、重试线程退出
   期间新终态到达：共 **5 failed → 5 passed**。恢复 schema 在提供按钮前校验；
   捕获 SQLite 底层数据库错误；每条终态独立退避，退出时在保存锁下清除线程引用。
7. 关闭中重试线程清除共享引用导致 `None.join()`、坏完成证据缺字段/错误日志类型
   污染待保存队列：新增组 **3 failed、1 passed → 4 passed**，后补缺 `error`
   参数。关闭捕获局部线程引用；证据完整校验先于写入内存待保存状态。
8. CLI 打开浏览器失败遗漏关闭、最后一次保存异常阻止释放已排空工作区：各先确认
   第二次 `create_app` 仍被拒绝，随后修复；服务器启动失败原本已正确。只有持久化
   写入者确实排空后才允许最终保存异常仍释放锁。

## 实际边界

证据通过临时文件写入、flush、fsync、原子替换；POSIX 额外同步父目录。这里验证的是
进程崩溃，不承诺断电一致性。SQLite 与完成证据同时不可写且进程随后退出时，无法
保证恢复内存结果；页面会显示 `evidence_saved=false`。自动尝试用尽后保留待保存结果
及背压，正常关闭再尝试，重启回放；不无限重试或无限等待永久保存失败。

锁约束参与本机制的工作台实例，不防止同权限外部程序主动替换锁文件或扫描篡改私有
暂存路径。恢复操作重新校验项目/路径/身份/摘要；不符即保留证据并拒绝，不根据路径
名称盲删或覆盖。任意长期不返回的用户工作函数/文件系统调用仍可能延迟关闭：为了
不让旧写入者和新实例并行，不能仅因等待超时就释放所有权。
