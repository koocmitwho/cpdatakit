# v0.8 dependency validation

The lower jobs use exact direct versions from `scripts/v06-dependency-candidates.json` and
Python-specific constraints in `scripts/constraints/`. The constraints also pin the resolved
runtime transitive dependencies. Test tools are resolved separately in the same pip transaction;
the full installation report records every installed version, wheel URL and archive hash.
Latest jobs resolve the newest versions allowed by the candidate wheel metadata.

Each cell builds a wheel from its sdist in a separate build environment. Tests, metadata and
examples are read from that same sdist snapshot. The wheel is installed in a clean test
environment, which checks exact lower versions and
`pip check`, imports dependencies, exercises NetCDF/Zarr/Parquet/FastAPI, runs the full test suite
with >=85% coverage, and starts Uvicorn for real HTTP requests to the health endpoint and static
assets. The test suite covers slice/draft/mapping/batch/tensile integration as well as legacy APIs.
Reports and logs survive failed cells. `passed` requires all stages to succeed.

## What lower means

This is a feasible lower combination, not proof that every declared minimum works together.
The runtime floor is now h5py >=3.11, Pint >=0.24.4 and netCDF4 >=1.7.2, based on the import failures below.
Other runtime declarations remain unchanged.

Initial wheel-only lowest-direct resolution on Windows/Python 3.12 selected h5py 3.10.0 and
Pint 0.22. Importing h5py with NumPy 2.0.0 failed with `numpy.dtype size changed`; Pint 0.22
failed because NumPy removed `cumproduct`. h5py 3.11.0 imported successfully. Pint 0.24
failed with the currently resolved parser dependencies; Pint 0.24.4 imported successfully.
Pint 0.23 also failed on `cumproduct`; 0.24.1–0.24.3 failed with the same parser/dataclass
error under the resolved transitive dependencies. These attempts remain under
`.artifacts/p0-explore-*` and `.artifacts/p0-pint-earlier.log`.

Python 3.12 direct lower choices include NumPy 2.0.0, pandas 2.2.2, h5py 3.11.0,
Matplotlib 3.8.4 and netCDF4 1.7.3. Python 3.13 wheel resolution requires NumPy 2.1.0,
pandas 2.2.3, h5py 3.12.1, Matplotlib 3.9.2 and netCDF4 1.7.2. Both use Pint 0.24.4.
Other direct pins are recorded in the candidate JSON. These are tested combinations, not
claims that every earlier release was exhaustively excluded on every operating system.

A real NETCDF3_CLASSIC write/read failed with netCDF4 1.7.1.post1 (`only endian=native
allowed`, file reports big endian). The same operation passed with 1.7.2. Logs are retained
as `.artifacts/p0-classic-repro.log` and `.artifacts/p0-netcdf172-read.log`.

The Linux/Python 3.12 combination h5py 3.11.0 + netCDF4 1.7.2 imported successfully, then
failed a NetCDF write when h5py was imported first. Reversing the imports passed. Both wheels
bundle HDF5 1.14.2 and a same-named high-level HDF5 library with different hashes. The loaded
library paths and import-order traces are retained in `.artifacts/p0-linux-hdf-libraries.log`
and `.artifacts/p0-linux-netcdf-diagnostic-*.log`.

Changing only netCDF4 to 1.7.3 passed both import orders and all format probes. The shared
Python 3.12 lower combination therefore pins 1.7.3. The runtime declaration remains >=1.7.2:
1.7.2 passed with h5py 3.12.1 on Python 3.13. This is a constraint on a dependency combination.

The h5py/Pint/netCDF4 metadata floors exclude the earlier isolated import/read failures. Platform wheel
availability and transitive requirements still mean that the oldest usable combination can
vary by Python version. The exact constraints state what each lower job actually exercises.

Windows and WSL Linux results, plus pending macOS/hosted CI cells, are listed in
[the verification record](verification/2026-09-08-v080-p0.md). Configured jobs alone are not results.
