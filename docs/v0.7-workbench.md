# v0.7：多维数据与本地工作台

v0.7 工作台支持从页面上传数据、选择 schema、验证、转换和查看报告。

## 从页面完成一次处理

安装 v0.7.0 后启动工作台：

```powershell
python -m pip install --upgrade cpdatakit==0.7.0
cpdatakit ui --workspace .cpdatakit
```

1. 创建项目，或从首页打开已有项目。
2. 选择内置 `curve`、`point`、`field2d`，或在 **Add a custom schema** 中上传 schema JSON。上传成功后，新 schema 会自动选中。
3. 用 **Upload and inspect** 上传数据文件。Zarr 使用 **Upload a Zarr directory**，选择整个 `.zarr` 目录。
4. 从 **Uploaded dataset** 选择数据，点击 **Validate dataset**。页面显示验证结果、字段问题和维度信息。
5. 选择输出格式和项目内输出路径，点击 **Convert dataset**。
6. 点击 **Create report** 生成 HTML、Markdown 或 JSON 报告。在 **View results** 打开报告或下载转换文件。Zarr 结果下载为包含完整目录的 ZIP。

转换和报告在后台运行，可在 **Jobs** 查看进度或取消任务。取消请求在下一个检查点生效，正在执行的底层读写会继续完成，已经写出的结果会保留。刷新页面可继续查看任务。服务重启后，已完成任务和结果仍可查询，未完成任务会标为中断失败。

页面用 **Validation passed / failed** 显示数据是否通过校验，并列出字段问题。转换要求校验通过，有问题的数据也可以生成报告。

## 格式与 schema

| 输入 | 数据模型 | schema | 可转换输出 |
| --- | --- | --- | --- |
| CSV、JSON records、Parquet、HDF5 1.0 | 表格 `Dataset` | 1.0，包括自定义 profile | HDF5 1.0、Parquet |
| NetCDF、Zarr 3、HDF5 2.0 | `ScientificDataset` | 2.0 | HDF5 2.0、NetCDF、Zarr 3 |

HDF5 是默认输出格式，表格写为 1.0，多维数据写为 2.0。其他可选格式见上表。多维数据按原有维度写出，单位按 schema 和数据中的声明检查。

NetCDF 经典格式使用 `netCDF4` 引擎，NetCDF4/HDF5 文件使用 `h5netcdf`。

schema 2.0 验证检查维度名称、长度和字段的维度顺序，核对坐标、变量、dtype 和单位，并报告缺失值、非有限值及未声明字段。数值统计按各数组分别计算。检查服务的 `record_count` 是首个数据变量的首维长度，完整形状见维度列表。

schema 1.0 沿用原有验证器。绘图接口支持内置和自定义 schema 1.0，当前页面提供验证、转换和报告操作。

## 自定义 schema

上传的 schema 保存在所属项目中，通过 `schema:<id>` 选择。该 ID 仅在所属项目内有效，浏览器接口按 ID 读取 schema。

网页接收独立 schema 或已解析的 schema 2.0 JSON。含 `extends` / `includes` 的组合 schema 先在 Python 中解析：

```python
import json
from pathlib import Path
from cpdatakit.schemas import resolve_schema_v2

resolved = resolve_schema_v2(Path("schema/composed.json"))
Path("schema-for-upload.json").write_text(
    json.dumps(resolved.schema.to_dict(), ensure_ascii=False, indent=2), encoding="utf-8"
)
```

网页保存解析后的声明。Python 应用服务也可直接接收本地组合 schema 路径。

## Python 应用服务

```python
from pathlib import Path
from cpdatakit.application import (
    ConvertRequest,
    DatasetRequest,
    ImportInspectRequest,
    import_and_inspect,
    validate_and_summarize,
    convert_and_write,
)

source = Path("thermal.nc")
schema = Path("schema-for-upload.json")
inspection = import_and_inspect(ImportInspectRequest(source))
checked = validate_and_summarize(DatasetRequest(source, schema))
converted = convert_and_write(
    ConvertRequest(
        source,
        schema,
        Path("results/thermal.h5"),
        workspace=Path.cwd(),
    )
)
```

`ConvertRequest.output_format` 默认为 `"hdf5"`，也接受 `"netcdf"`、`"zarr"`、`"parquet"`。服务返回 `ServiceResult`，失败时包含错误码和说明。

科学数据转换保存输入文件名、输入哈希、操作记录和本次验证摘要。计算目录哈希时，先按相对路径排序，逐项加入 UTF-8 路径、NUL、文件 SHA-256 的 ASCII 十六进制文本和换行，再计算 SHA-256。

## 上传与文件管理

数据上传默认上限为 64 MiB，结构检查默认上限为 10,000 条记录 / 64 MiB。Zarr 按目录累加大小，最多接收 1,000 个文件。schema JSON 最多 1 MiB，同时受配置的上传上限约束。

新格式的结构检查读取元数据，完整验证、转换和报告会加载数据。处理压缩文件时，需要为解压后的数据预留内存。

上传失败会清理本次暂存内容，修正后可使用原文件名重试。再次上传同名文件时，先给文件重命名。替换已有输出需勾选页面上的替换选项。`uploads`、`schemas` 和 `.artifacts` 是保留目录，输出写入其他项目目录，例如 `results`。

本地服务使用 loopback Host 检查、会话与 CSRF 校验。下载接口提供项目已登记的结果，HTML 报告在浏览器沙箱中显示。

每次产物登记前，工作台将结果复制到项目内独立的 `.artifacts/version-…/` 目录。
用户指定的输出文件仍可直接使用；任务返回值和结果列表指向已登记的独立版本。
覆盖同名输出不会改变已有版本，历史副本会占用额外磁盘空间。

下载前会在工作线程中核对内容哈希：文件使用 SHA-256，新目录产物使用相对路径与成员
文件哈希构成的目录哈希。旧比较包仍按原有 manifest 哈希读取。内容与登记信息不符时，
接口返回 `409 artifact_changed`。旧版本没有快照且已被覆盖的内容无法由哈希恢复；
这类记录会拒绝下载替换后的内容。

## 兼容性

v0.5 的公共导出、函数签名、CLI 参数、内置 schema JSON/hash、schema 1.0、HDF5 1.0 和 DAMASK 行为沿用原有契约。新增格式通过 `cpdatakit.application` 读取，`cpdatakit.load_dataset()` 继续处理 CSV、JSON records 和 HDF5 1.0。运行时依赖和 Python >=3.12 的要求沿用 v0.6.1。
